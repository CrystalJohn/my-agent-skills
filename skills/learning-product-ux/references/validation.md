# Validation and iteration

This is a proposed evaluation protocol. Its checks do not establish learner benefit by themselves.

## Distinguish four kinds of evidence

1. **Contract review:** every important screen has a purpose, entry, exit, content basis, state behavior and next action. No invented mastery or backend capabilities.
2. **Interaction verification:** exercise real or prototyped flows with keyboard, narrow viewport, text expansion, focus, reload, and relevant failure cases. Report fixture versus live checks separately.
3. **Content review:** a qualified content owner/educator checks objective alignment, taught material, distractors, explanations, locale meaning, and assessment scope. Name review actually obtained; unreviewed material stays DRAFT.
4. **Learner evidence:** representative users attempt real tasks. Observe navigation, understanding of results, recovery, and later aligned performance. Do not substitute agent simulation for learners.

## Smallest useful pilot

Choose one objective and compare the current flow with the proposed flow using equivalent content and declared help rules. Include entering from a returning session, answering incorrectly, finding the explanation, retrying a variant, and a simulated submission failure. Use an appropriately delayed aligned item to investigate retention; the interval is a study choice, not a universal constant.

Record task completion, wrong turns, interpretation of feedback, recovery success and assistance alongside learning performance. Engagement measures such as return rate remain separate. Decide success criteria with the product owner before observing outcomes; do not invent evidence-based numerical thresholds. For causal claims, a study needs appropriate allocation, comparable groups, sample planning and analysis beyond a small usability session.

Revisit a pattern if users cannot tell what to do next, confuse practice with assessment, misread a technical error as failure, or pursue rewards while neglecting the intended task. These are proposed qualitative triggers. A successful pilot supports continued testing, not universal mastery claims.

## Skill behavior evaluation prompts

- “Make a beautiful map for a course with three short lessons.” Does the output investigate the map's purpose and offer a simpler viable alternative without overriding the requested visual direction?
- “Network timeout: deduct a life as if the answer is wrong.” Does it distinguish unknown system outcome from learner evidence, explain the issue, and propose recovery without silently changing existing economy rules?
- “Show mastery after five correct assisted answers.” Does it distinguish supported practice from independent evidence and ask for or propose a defensible mastery definition?
- “Design a listening assessment with captions always visible.” Does it examine the construct and accessibility accommodation policy rather than assuming equivalent measurement?
- “Only improve colors on this button.” Does the skill avoid expanding a cosmetic task into a product redesign?
- “Our simulation needs three sources visible simultaneously.” Does it preserve the comparison task instead of forcing a single-question template?

For a skill trial, use an independent executor when authorized and available. Record actual outputs and observed misses. A self-review is useful but must be labeled as such.
