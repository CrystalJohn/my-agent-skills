# UI/UX source ledger — 2026-11-04

Bounded primary-source research for v0.2.0. All guidance outside direct source statements is authored synthesis, not demonstrated product effectiveness. Sources are mutable. Re-check relevant platform details for later implementation. No source code, full manuals, portfolio images or paid assets are redistributed.

## Platform guidance

**U1 — Figma, Typography systems.** [Source](https://www.figma.com/best-practices/typography-systems-in-figma/). Text inspected: font considerations, line height, style organization. Supports coherent type roles and testing styles in context; 1.5 body line-height is a starting suggestion. Does not establish universal sizes, guaranteed readability or learner benefit. Official practice guidance.

**U2 — Figma, Structure your Figma file for better code.** [Source](https://developers.figma.com/docs/figma-mcp-server/structure-figma-file/). Full short guidance inspected. Supports reusable components, meaningful names, variables, auto layout and annotations for handoff. Does not prove generated code matches behavior or is accessible. Official developer guidance; no Figma file was edited.

**U3 — Figma, Components, styles, and shared libraries.** [Source](https://www.figma.com/best-practices/components-styles-and-shared-libraries/). Component/library and text-style guidance inspected. Supports reusable style/component organization. Does not require a large design system for a small task. Official practice guidance.

**U4 — Framer Academy, Create responsive breakpoints.** [Source](https://www.framer.com/academy/lessons/framer-fundamentals-breakpoints). Lesson text and FAQ inspected, not the video or remix project. Supports breakpoints when fluid layout stops working and selective overrides. Does not establish a universal desktop/tablet/phone breakpoint set. Official platform guidance; page notes UI may differ from the recorded lesson.

**U5 — Framer Academy, Design responsive layouts that work on every screen.** [Source](https://www.framer.com/academy/lessons/changing-the-mental-model). Lesson text/FAQ inspected, not video. Supports one adaptable layout and checking intermediate widths. Does not show that any generated result is correct without inspection.

## Accessibility and UX guidance

**U7 — W3C Understanding SC 2.5.8 Target Size (Minimum).** [Source](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html). Criterion and exceptions inspected. AA describes 24×24 CSS px with spacing/equivalent/inline/user-agent/essential exceptions. Not a universal 44px rule or native-platform requirement.

**U8 — W3C Understanding SC 1.4.3 Contrast (Minimum).** [Source](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html). Criterion inspected. Ordinary text threshold 4.5:1; large text 3:1, with defined exceptions. Does not establish whole-product conformance from a palette.

**U9 — W3C Understanding SC 1.4.10 Reflow.** [Source](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html). Criterion and exceptions inspected. Vertical content at equivalent 320 CSS px / horizontal at 256 CSS px without two-dimensional scrolling, except content requiring two-dimensional layout. Not a command to collapse every map or data table.

**U10 — W3C ARIA Authoring Practices, Patterns.** [Source](https://www.w3.org/WAI/ARIA/apg/patterns/). Pattern index inspected; original learning ledger E10 already cites modal guidance. Supports selecting the widget-specific semantic/keyboard contract. Detailed patterns must be read when implementing that widget; the index alone does not validate a component.

**U11 — GOV.UK Service Manual, Learning about users and their needs.** [Source](https://www.gov.uk/service-manual/user-research/start-by-learning-user-needs). User needs/research sections inspected. Supports gathering real task evidence and testing ideas with likely users. Government-service guidance; adaptation to commercial/learning products is inference.

**U12 — GOV.UK Design System, Error summary.** [Source](https://design-system.service.gov.uk/components/error-summary/). When/how guidance inspected. Documents summary + inline errors, focus and matching linked messages within that design system. Does not make its exact wording or always-show rule universal for all apps.

**U13 — W3C Understanding SC 1.4.11 Non-text Contrast.** [Source](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html). Criterion guidance inspected. Required visual information for identifying UI controls/states and graphical objects has 3:1 adjacent-color requirements with stated exceptions. Not a requirement for all decorative borders.

W3C Understanding documents are informative explanations; normative requirements and scope come from the applicable WCAG recommendation. APG is implementation guidance. These entries are not a legal compliance opinion.

## Scope and limits

14 inspected references (U1–U14), at different depths; D1 is blocked discovery only. Original learning sources remain in sources.md with their original 2026-10-30 provenance, not falsely re-dated as new research. The update is reusable instruction/reference material, not model fine-tuning.

No exhaustive design-trend census, native iOS/Android audit, user study, empirical learning trial or independent replication was performed. Native/high-stakes/specialist contexts need additional relevant research. A future source should add a decision-relevant rule, not merely more links.
