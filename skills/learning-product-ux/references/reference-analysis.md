# Learning from design references

Use for requested research or supplied Figma, Framer, Behance, Dribbble and similar examples. This builds a reusable evidence base, not model retraining. Consult [ui-sources.md](ui-sources.md) for this package's actual source coverage.

## Source roles

- Figma official documentation: component structure, styles/variables, layout relationships and handoff. A community file is an individual artifact with its own license and quality.
- Framer official documentation/live examples: adaptable layout, breakpoints and implemented interactions. A template preview is not evidence of its customers' outcomes.
- Behance case studies: visual direction and reported design process. Separate visible screens from author claims about research.
- Dribbble shots: composition, emphasis, typography, color and motion ideas. Cropped hero shots rarely establish complete flow or error behavior.
- W3C and relevant platform documentation: accessibility requirements/guidance; portfolio popularity cannot override them.

For important behavioral decisions, pair inspiration with official guidance and task-specific observation. Likes, awards and polished mockups do not validate UX.

## Bounded collection

Start from a specific design question (e.g. "preserve comparison on a narrow teacher dashboard"). Select a small diverse set with a reason for inclusion, not dozens of near-identical shots. Include a plausible alternative when it changes the decision. Stop when new examples no longer change it; expand if relevant evidence remains missing.

Open the actual page. Inspect images visually before describing appearance. Read the case-study section before repeating its claims. Use a live preview when behavior matters and is accessible. Record date, author, URL, inspected region and evidence mode: text, image, live interaction, author report, discovery only, or blocked. Do not solve access challenges, buy templates or change accounts just to fill a reference quota.

If a source is inaccessible, state the limit, use an accessible alternative for the decision, and preserve the blocked item only as a discovery lead. Search snippets are discovery, not full inspection.

## Reference card

Record only useful details:
- Source/author/date/URL and what was actually inspected.
- Relevant task, platform, viewport and content density.
- Observable composition, type roles, emphasis, surfaces and component anatomy.
- Behavior observed versus inferred; states not shown.
- Transferable principle and proposed adaptation to this product.
- Strongest alternative and condition favoring it.
- Failure risk (e.g. tiny labels, competing actions, unrealistic content, hidden recovery).
- Verification needed and asset reuse status.

Exact colors, font names, dimensions or animation timing require evidence; otherwise label estimates. A palette listed by the site need not equal the rendered interface's semantic tokens.

## Synthesize into original design

Translate an observation into a conditional rule:
"One dominant resume action may help a returning learner find unfinished work; test against direct resume when only one activity exists."
Do not write:
"Popular dashboards always have four stat cards."

Keep typography/layout/behavior lessons separate so unrelated references do not become a collage of incompatible styles. Choose a direction that serves the brief, then test it with real content and unavailable/error states. Redraw original compositions and use permitted assets. Public visibility does not grant redistribution rights.

## Updating this knowledge base

Add a rule only if it changes a recurring decision. Each source entry should say what it supports, what it does not establish, access depth/date and limitations. Keep raw research notes outside the installed skill. Maintain a small set of conditional references rather than a copied image library or full manuals.

An update should be checked against representative tasks: a narrow cosmetic edit, general product flow, visual redesign, source-inaccessible request, and learning/assessment case. Record actual outputs and misses; self-review is weaker evidence than an independent trial and never replaces real users.
